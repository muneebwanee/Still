# Release validation

This repository contains an implementation, not evidence of an already validated App Store release. No signed or unsigned IPA was produced in the authoring environment because Apple’s SDK and signing credentials are unavailable there.

Completed here: nine Node remote logic tests; five offline-document consistency tests; eight relay socket tests; browser WebRTC over loopback TURN/TCP with a canvas source; Android Java compilation against API 36; a Swift syntax parse (not SDK type checking); headless Chromium browser integration with an HTTP fixture; visual inspection of the browser remote; plist, asset JSON and YAML parsing; build-script syntax validation.

Before distribution:

- Supply the distributor’s actual legal name, mailing address, telephone number and support contact in the custom Store EULA/store listing. The current draft uses the known GitHub identity and expressly records the missing store details. Review NCL 1.0 and all legal documents for your intended distribution.
- Run the macOS Actions workflow and resolve any compiler, SDK or Swift test failures. Neither native compilation nor Swift tests ran in the Linux authoring environment.
- Install on a real iPhone and iPad. Test first-start permission allow/deny, denial recovery through Settings, foreground/background, Wi-Fi changes, router isolation and multiple remotes. Test service startup on a clean install: permission timing and Network.framework behavior need device evidence.
- Test YouTube iframe playback on each supported OS with embeddable, restricted, live and unavailable videos. Validate origin/referrer behavior, autoplay restrictions, offline errors and player controls. If YouTube rejects the WKWebView origin context, resolve that before claiming YouTube support in a release.
- Test MP4, audio and adaptive HLS sources, live media, expired URLs, invalid certificates, subtitles through native controls, quality ceilings, buffering, queue transitions and full screen. Verify repeat, speed, saved preferences, queue-only enforcement (including an idle receiver), YouTube-off behavior, disconnect-all, sleep expiry and partial/complete local wipes. The UI tests are authored but have not run in this workspace. Check interruptions from phone calls and headphones.
- Check VoiceOver, the largest Dynamic Type sizes, increased contrast, Reduce Motion, both themes, rotation, iPad multitasking and small iPhones. Profile the actual device with Instruments before making performance claims. No frame-rate or battery claims have been measured.
- Supply your own bundle ID, signing team, certificate and provisioning profile. Confirm App Store export or registered ad hoc devices as appropriate.
- Host the privacy policy and terms at stable public URLs (for example via GitHub Pages); the in-app pages and Markdown originals are supplied. Provide App Store privacy answers that accurately reflect the final app and embedded third-party media. Review legal text, support contact, content rights, YouTube API terms and branding for your release and jurisdiction.
- Prepare real device screenshots, review instructions and metadata explaining the local-network foreground receiver and browser pairing. The app must not be marketed as a Google Cast/AirPlay receiver or universal screen-mirroring app. Distinguish supported Android/desktop video-only sharing from unsupported iPhone/iPad sending and proprietary Cast protocols.

New in 1.2: build and run the two native recording tests and validate video rotation, save/error paths, low-storage stops, interrupted finalization, incomplete-file cleanup, deletion and wipe. Test actual Android-to-iOS and browser-to-iOS capture on real devices, including revocation, rotation and lock. Deploy HTTPS and TURN on a real domain and verify separate networks, UDP/TCP/TLS relay paths, quotas, access controls, retention and operating costs before offering internet sharing. The included Docker/TURN templates have not been deployed here. Validate native stream PiP and actual background audio on physical devices; screen receiving and local commands must still stop. Review third-party binary notices, privacy-manifest behavior and export/encryption compliance for WebRTC. No default cloud service, native media test result or export exemption is implied.

The source privacy manifest declares the app’s own UserDefaults access (`CA92.1`), no tracking SDK and no app-side data collection. YouTube and stream hosts process playback requests under their own policies; the manifest does not replace App Store privacy review of the final product.
